PBKDF2-SHA1 CPU kernels: verification and measurements, 2026-11-15

Scope

Native API 16 adds PBKDF2-HMAC-SHA1 for WinZip AES (13600) and WPA (22000),
including mask and file-wordlist hybrid. No commits, staging or publication.
All results below were measured in this run. Earlier partial work supplied no results.

Failures found and resolved

Initial native build was blocked by sandbox access to the installed compiler
cache; rebuilt outside the sandbox. The .NET test runner also required loopback
socket access outside the sandbox. A sandboxed full-solution build stalled
without output and was terminated; the retry outside the sandbox passed in 2.56 s.
Initial restore lacked asset files and could
not retrieve vulnerability data; packages restored from local cache, subsequent
commands disabled that network audit. No software or packages were downloaded.

Regression tests exposed missing dictionary registrations, zero-prefix division,
WPA raw-line potfile keys and byte-changing dictionary cache reads. All were fixed.
The first WPA GPU dictionary fixture used a seven-byte source word plus append
rule and exhausted. hashcat 8 filters that source word before applying the GPU
rule. The passing comparison uses an eight-byte source and a substitution rule.
That upstream short-source/rule behavior is outside this change; native checks
accept the correctly expanded 8-63-byte candidates.
The standalone Windows check initially expected only AVX2 in a cumulative path
mask; its one-iteration fixture correctly records scalar too. Correcting the
checker expectation produced the passing results above.

M1 Pro complete mask jobs

Private hashcat 8.0.0, Metal GPU, native ARM SHA-1, 9 CPU workers in hybrid.
Both modes offer only pure GPU kernels according to this copy's --hash-info.
Eight-byte candidates, password absent, all jobs exhausted the complete space:
  WinZip: ABCDEFGH at every position, 16777216 candidates.
  WPA: ABCDEF at every position, 1679616 candidates.
The targets were the same published example hashes as bench-native.

Generic command:
  dotnet src/RecoverKit.Cli/bin/Release/net10.0/recoverkit-cli.dll crack MODE.hash --hash-mode MODE --hashcat PRIVATE_HASHCAT --hcmask '?1?1?1?1?1?1?1?1' -1 CHARSET --strategy GpuOnly --threads 9 HYBRID_OPTION --no-potfile --new
HYBRID_OPTION was --no-hybrid or --hybrid. Automatic calibration was disabled
and speed/startup caches cleared before each job to measure a fresh hybrid split.
Three adjacent pairs per mode; pair order was reversed in the second round.
Elapsed values below are the CLI's whole-job seconds, including hashcat startup.

Mode   GPU alone, seconds           Hybrid, seconds               Change
13600  22.698, 22.586, 22.779        28.444, 28.790, 28.444         24.9-27.5% longer
22000  19.001, 18.381, 18.963        33.980, 33.881, 33.475         76.5-84.3% longer

Reported live samples while both engines were active, candidates/s:
  WinZip GPU alone: 814514-875180; hybrid total: 914338-956362.
  WPA GPU alone: 100722-104974; hybrid total: 112664-120130.
Higher combined rates did not offset the CPU tail after hashcat finished.
These are fresh-cache finite jobs, not evidence for every duration or cached split.
A subsequent WPA CLI job retained the measured speeds and explicitly printed
that the CPU added less than a quarter of the integrated GPU's speed, then ran
hashcat alone. The existing drop rule and new-format planner tests both passed.

Ryzen estimate and remaining verification

An illustrative same-throughput-per-thread extrapolation from the M1's ARM SHA-1
medians to 16 threads gives about 226000/s WinZip and 27700/s WPA. Against the
previously supplied GPU baselines (not remeasured here), that would contribute
roughly 6.5% and 5.7% of combined throughput. This is a rough model, not a Zen 5
prediction: AVX-512 has twice AVX2's lanes, while clocks, instruction throughput
and SMT differ from the M1. Worth measuring on the discrete-GPU system; a net
benefit has not been established. It was not worth hybrid on these M1 finite jobs.

Departures and limits

Format authentication uses .NET primitives after native PBKDF2; new dependencies
were unnecessary. Nonce-corrected EAPOL and PSK-SHA256 PMKID targets remain wholly
on hashcat. No scheduler retuning was made to conceal the M1 finite-job slowdown.
The shared performance plan in the other checkout was read but not changed.
