TrueCrypt/VeraCrypt SHA-512 CPU engine, 2026-11-16 to 2026-11-17

Scope

Native API 17 adds reusable SHA-512 compression and PBKDF2-HMAC-SHA512.
The CPU kernel covers emitted modes 29321-29323 and 29421-29423, and legacy
aliases 6221-6223 / 13721-13723. The second/third modes also test shorter
cipher chains, with their own XTS key layouts. Header offsets, including
hidden volumes, do not change the CPU check.

TrueCrypt: AES, Serpent, Twofish; AES-Twofish, Serpent-AES, Twofish-Serpent;
AES-Twofish-Serpent and Serpent-Twofish-AES.
VeraCrypt adds Camellia, Kuznyechik; Camellia-Kuznyechik, Camellia-Serpent,
Kuznyechik-AES, Kuznyechik-Twofish; Kuznyechik-Serpent-Camellia.
TrueCrypt passwords: 0-64 bytes. VeraCrypt: 0-128 bytes in manual/dictionary
jobs; the existing extracted-volume target retains its 64-byte cap.
Every CPU hit is rederived with Bouncy Castle and checked by the managed
header verifier before reporting. Default single-header SHA-512 GPU and cached
hits use the same managed confirmation; existing additional confirmations are
preserved. Credential and extra-argument jobs retain hashcat handling. Kuznyechik uses a local RFC 7801 reference
because Bouncy Castle 2.7 lacks that cipher.

Keyfile and nondefault PIM jobs retain the existing VolumeCredentials gate:
the whole job stays on hashcat, including rules, masks and resume. The direct
kernel/reference supports a fixed PIM and tests 15000 + 1000 * PIM iterations;
that does not enable CPU partitioning of credential-bearing recovery jobs.
No candidate subset is assigned to an unsupported CPU variant.

Hybrid defaults to CPU plus a discrete GPU. Integrated-only systems retain
hashcat unless explicitly selected or a measured profile selects hybrid.
A CPU-only job requires the existing measured execution-winner gate.
No commits, staging, publication or changes to other worktrees.

Real hashcat verification

RECOVERKIT_TEST_HASHCAT pointed at this task's private hashcat 8.0.0 copy.
The opt-in run passed 19/19: 17 SHA-512 tests and two existing Whirlpool
matched-probe cases. It covered all six published examples, every cipher and
cascade listed above, custom PIM, and GPU/hybrid masks and rule dictionaries.
The published VeraCrypt 1536-bit example initially timed out after three
minutes. An isolated visible run passed its self-test but had completed only
86154/500000 iterations when a 20-second attack limit expired. Default startup
alone took 118 seconds. The final eight-minute correctness budget passed the
example in 3 minutes 11 seconds. No hashcat self-test or kernel error occurred.
Grouped generated headers use unique salts: these hashcat modes reject multiple
headers with one salt. Generated VeraCrypt cases use PIM 1 to check each cipher
without repeating a 500000-iteration KDF for each independent header.

Native verification and dispatch

Both targets built with native/build.sh and cached Zig 0.15.2:
  ZIG_GLOBAL_CACHE_DIR=/tmp/recoverkit-zig-cache ZIG=<cached-zig-binary> sh native/build.sh
  win-x64 and osx-arm64: zero compiler warnings.
The installed anyzig wrapper could not use its normal compiler cache inside
the sandbox; using its already-cached compiler and a writable temporary cache
worked without installing software.

Mac: 240 randomized Python hashlib comparisons across scalar, NEON, ARM SHA-512
and default, including password/salt lengths 0-256, HMAC boundaries 128/129,
salt padding boundaries, iterations 1/2/7/1000, output lengths 1/63/64/65/128/192,
zero and partial groups, output sentinels, invalid arguments and passed guards.
Windows VM: API 17, features 5 (AVX2 + AES), no .NET runtime installed.
Four fresh processes, scalar/AVX2/default/requested-AVX512 fallback, passed
1548 hashlib comparisons over 72 batches per process, plus invalid arguments
and feature masking. AVX-512 execution is unavailable on this VM.

Default x64 path: AVX-512 eight lanes, otherwise AVX2 four lanes, otherwise scalar.
Default arm64 path: FEAT_SHA512 two interleaved streams, otherwise NEON two lanes,
otherwise scalar. Each accelerated implementation has its own independent
known-answer guard before candidate work; a failed guard uses scalar.
RECOVERKIT_PBKDF2_SHA512_AVX512=0 disables the wide x64 path.
RECOVERKIT_PBKDF2_SHA512_PATH selects scalar/neon/arm-sha512/avx2/avx512.
The selected-path export and executed-path bits distinguish fallbacks; timings
are rejected if the requested path did not execute.

M1 Pro recoverkit-cli measurements

All 108 accepted native-only samples: six modes, scalar/NEON/ARM SHA-512,
one and ten threads, three repeats each. Every accelerated row printed the
requested executed path and a passed guard. Unsupported x64 paths were not
timed on this Mac. No managed-only throughput claim is made.

Command, with a private RECOVERKIT_HOME and one fresh process per sample:
  RECOVERKIT_PBKDF2_SHA512_PATH=PATH dotnet src/RecoverKit.Cli/bin/Release/net10.0/recoverkit-cli.dll bench-native --mode MODE --threads THREADS --seconds SECONDS --length 7

Requested duration was 4 seconds for TrueCrypt and 6 for VeraCrypt. The rate
excludes the first one-second warmup. In-flight batches finish before stopping,
so VeraCrypt process elapsed time was 6.38-9.24 seconds. Priority was the default Idle;
threads were not pinned to the M1 Pro's performance/efficiency cores.

CPU samples waited for known concurrent CPU/GPU tests to stop. A process
monitor checked for active hashcat jobs and heavy dotnet/Python/compiler
processes during each sample; detected overlaps were discarded and repeated.
The initial contended pilot and whole-number VeraCrypt pilot were discarded.
Normal OS activity and scheduling are not eliminated. Short windows on slow
fallback paths remain sensitive to batch completion; the three runs expose
that spread rather than hiding it.

Windows verification and measurements

Use a private hashcat 8.0.0 copy and the freshly built native DLL. From the
repository root in PowerShell:

  $env:RECOVERKIT_HOME = Join-Path $env:TEMP 'rk-truecrypt-sha512'
  $env:RECOVERKIT_TEST_HASHCAT = 'C:\bench\hashcat\hashcat.exe'
  $cli = 'src\RecoverKit.Cli\bin\Release\net10.0\recoverkit-cli.dll'
  # With Zig 0.15.2 already installed; rebuild the Windows DLL first.
  New-Item -ItemType Directory -Force native\bin\win-x64 | Out-Null
  zig cc -target x86_64-windows-gnu -O3 -std=c11 -Wall -Wextra -Wno-unused-function -Wno-unused-const-variable -fno-strict-aliasing -shared -o native/bin/win-x64/rknative.dll native/rknative.c
  dotnet build RecoverKit.sln -c Release -p:NuGetAudit=false
  dotnet test tests/RecoverKit.Tests -c Release -p:NuGetAudit=false
  dotnet test tests/RecoverKit.Tests -c Release -p:NuGetAudit=false --filter 'FullyQualifiedName~TrueCryptSha512HashcatTests'
  dotnet $cli bench-full --hashcat $env:RECOVERKIT_TEST_HASHCAT --sections cpu,gpu,hybrid --thorough --out (Join-Path $env:RECOVERKIT_HOME 'sha512.html')

The six published examples retain hashcat's full default-PIM self-tests.
Generated headers are grouped by mode with unique salts; VeraCrypt fixtures
use PIM 1, and only those independent GPU oracle runs skip the redundant
hashcat internal self-test. Every digest must be recovered as the expected
password and every outfile line is counted. Native path guards stay enabled.
The opt-in suite also checks PIM 7 and mask/rule-dictionary GPU/hybrid recovery.

For direct path comparisons on the tester's 16-thread Ryzen:

  foreach ($mode in 29321,29322,29323,29421,29422,29423) {
    foreach ($threads in 1,16) {
      foreach ($round in 1..3) {
        foreach ($path in 'scalar','avx2','avx512') {
          $env:RECOVERKIT_PBKDF2_SHA512_PATH = $path
          dotnet $cli bench-native --mode $mode --threads $threads --seconds 10 --length 7
        }
      }
    }
    & $env:RECOVERKIT_TEST_HASHCAT -b -m $mode -D 2 -w 3
  }
  Remove-Item Env:\RECOVERKIT_PBKDF2_SHA512_PATH

Check the printed executed path and guard, not just the requested selector.
Run the same commands at 15 threads for the CPU's contribution next to the RTX
4060. Native-only plus GPU-only rates are not a measured simultaneous rate;
the complete hybrid section measures both running together and includes startup
and the CPU tail. Compare complete-job elapsed time as well as candidates/s.
The default measured-choice gates also protect CPU-only and integrated systems.
To compare hashcat CPU speed where a CPU OpenCL runtime is already available:

  & $env:RECOVERKIT_TEST_HASHCAT -I
  & $env:RECOVERKIT_TEST_HASHCAT -b -m 29321 -D 1 -w 3

Guard-off regression:

  $env:RECOVERKIT_PBKDF2_SHA512_AVX512 = '0'
  dotnet test tests/RecoverKit.Tests -c Release -p:NuGetAudit=false --filter 'FullyQualifiedName~TrueCryptSha512Tests'
  Remove-Item Env:\RECOVERKIT_PBKDF2_SHA512_AVX512

Limits

No Zen 5/RTX 4060 rates or AVX-512 execution results were measured here. The
supplied tester GPU baseline and commercial comparison are not remeasured by
these Mac/VM checks. No throughput extrapolation to that PC is claimed.
Keyfile and PIM recovery jobs intentionally remain on hashcat; direct PIM
reference tests do not change that planner boundary.
